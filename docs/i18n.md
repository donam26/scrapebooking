# Song ngữ (i18n): Tiếng Việt / English

Tài liệu chuẩn cho mọi chữ người dùng nhìn thấy: dashboard, landing, API, email, CSV, bản tin.
Tiếng Việt là ngôn ngữ nguồn và mặc định. Thêm ngôn ngữ thứ ba xem mục cuối.

## Kiến trúc

```
Trình duyệt ── cookie NEXT_LOCALE (vi|en) ──► Next.js (next-intl, không tiền tố URL)
   │                                             │  src/i18n/request.ts: đọc cookie → locale + messages
   │  nút VI|EN (components/locale-switcher)     │  <html lang>, metadata, server + client component
   │  → server action setLocale → router.refresh │
   ▼                                             ▼
/api/* (route.ts) ── Accept-Language: <locale> ──► FastAPI: app/i18n (get_locale) dịch text API sinh ra
                                                    email/bản tin: theo ngôn ngữ báo cáo của tenant
```

- **URL giữ nguyên** (`/dashboard`, không có `/en/dashboard`). Ngôn ngữ nằm ở cookie `NEXT_LOCALE`
  (1 năm). Chưa có cookie → tiếng Việt.
- **Đổi ngôn ngữ không mất state**: `router.refresh()` render lại server, client giữ form/tab.
  `useApi` có locale trong key nên dữ liệu có text do backend dịch được tải lại.
- **Text do backend sinh ra** (lý do gợi ý giá, lỗi URL watchlist, tên ngày lễ, CSV) dịch ở
  backend theo `Accept-Language` mà proxy `/api` đặt từ cookie.
- **Lỗi API**: backend giữ thông điệp tiếng Anh ổn định (`detail`), frontend khớp quy tắc trong
  `src/lib/errors.ts` → khoá `errors.*`. `ApiError.message` là chuỗi gốc (cho log).
- **Email, bản tin AI, báo cáo tuần**: không có người xem trực tiếp nên theo **ngôn ngữ báo cáo
  của tenant** (`tenants.insight_language`, Cài đặt › Lịch quét).

## Frontend (dashboard/)

### Tệp

| Đường dẫn | Vai trò |
|---|---|
| `src/i18n/config.ts` | `LOCALES`, `DEFAULT_LOCALE`, `INTL_LOCALE` (vi-VN, en-GB), tên cookie |
| `src/i18n/request.ts` | cấu hình next-intl theo request (cookie → locale, nạp messages) |
| `src/i18n/actions.ts` | server action `setLocale` |
| `src/i18n/server.ts` | `getFmt()` cho server component async |
| `src/i18n/next-intl.d.ts` | khoá bản dịch có kiểu (sai khoá = lỗi tsc) |
| `src/messages/<locale>/<namespace>.json` | bản dịch, mỗi namespace một tệp |
| `src/messages/<locale>/index.ts` | gộp namespace; `vi` là nguồn của kiểu `Messages` |
| `src/lib/format.ts` | hàm thuần + `useFmt()` (số, tiền, ngày theo ngôn ngữ) |
| `src/lib/labels.ts` | mã + màu trạng thái; `useLabel()` đọc chữ ở `labels.json` |
| `src/lib/errors.ts` | quy tắc dịch lỗi backend; `useErrorMessage()` |
| `scripts/i18n-check.mjs` | `npm run i18n:check` |

### Namespace

Một namespace cho mỗi khu vực màn hình, tên trùng thư mục route: `dashboard`, `availability`,
`rates`, `settings`… Dùng chung: `common` (hành động/trạng thái chung, metadata), `format`,
`labels`, `errors`, `shell` (khung app), `components` (components/ dùng chung), `helpers`
(lib/ sinh chữ). Trong namespace, khoá lồng theo component/khối: `settings.watchlist.addButton`.

- Khoá camelCase, đặt theo **ý nghĩa** (`emptyTitle`, `scanNow`), không theo nội dung chữ.
- Cùng chữ ở hai màn khác nhau vẫn để hai khoá: ngữ cảnh khác thì bản dịch có thể khác.
- Dùng lại `common.*` chỉ khi đúng nghĩa chung (Lưu, Huỷ, Đang tải…).

### Cách dùng

```tsx
// client hoặc server component (không async)
const t = useTranslations("settings.watchlist");
const { fmtMoney, fmtNight } = useFmt();
const label = useLabel();
const errorText = useErrorMessage();

t("title");                                  // chuỗi thường
t("roomsLeft", { count: 3 });               // tham số
t.rich("hint", { b: (c) => <b>{c}</b> });   // có thẻ: "Bấm <b>Lưu</b> để…"
label("eventType", ev.event_type);           // mã backend -> nhãn ("—" khi rỗng, mã lạ giữ nguyên)
fmtMoney(price, "VND");                      // 1.250.000 ₫ / ₫1,250,000

// server component async, generateMetadata
const t = await getTranslations("rates");
const { fmtDate } = await getFmt();
export async function generateMetadata() { const t = await getTranslations("rates.meta"); return { title: t("title") }; }
```

**Helper ngoài React** (lib/*.ts, hằng số cấu hình): không gọi hook. Hoặc trả về *khoá* (`key` +
`values`) để component dịch, hoặc nhận `t` / `fmt` / `label` làm tham số:

```ts
export function nightReason(n: Night, t: Translator<"helpers.nightReason">, fmt: Fmt): string
// kiểu translator: ReturnType<typeof useTranslations<"helpers.nightReason">>
```

Mảng cấu hình (tab, cột, tuỳ chọn select) giữ `key`, chữ lấy lúc render: `{ href, key: "rates" }` →
`t(\`nav.${item.key}\`)`. Với union đã biết, khai kiểu key để tsc kiểm tra.

### Quy tắc viết bản dịch

- **Câu đầy đủ có tham số**, không ghép mảnh: `t("scannedAt", { when })`, không `"Quét lúc " + when`.
  Thứ tự từ khác nhau giữa hai ngôn ngữ.
- **Số nhiều**: tiếng Việt không chia số nhiều (`"{count} phòng"`); tiếng Anh dùng ICU
  `"{count, plural, one {# room} other {# rooms}}"`. Hai bản phải cùng tên tham số.
- **Ký tự đặc biệt ICU**: `{` `}` là cú pháp; muốn hiện dấu nháy đơn cạnh `{` phải viết `''`.
  Thẻ `<b>` chỉ dùng với `t.rich`.
- **Tiếng Anh**: ngắn gọn, chữ hoa đầu câu (sentence case), chính tả Anh-Anh khớp `en-GB`
  (colour, cancelled), thuật ngữ ngành khách sạn: occupancy, ADR, RevPAR, rooms left, sold out,
  pickup, pace, comp set, rate parity, stay date, lead time. Giữ nguyên tên kênh và "OTARadar".
- **Không dịch**: tên kênh (`CHANNEL_LABEL`), tên khách sạn/thành phố trong dữ liệu, mã kỹ thuật
  (tenant, scraper, proxy… nếu bản Việt cũng để tiếng Anh). Lỗi chỉ dành cho lập trình viên
  (`throw new Error("useSession must be used inside SessionProvider")`) viết tiếng Anh, không dịch.
- Dòng cố ý giữ chữ tiếng Việt (tên riêng, dữ liệu minh hoạ địa phương): thêm comment
  `// i18n-ignore` cùng dòng hoặc `// i18n-ignore-next-line` ở dòng trên.

### Kiểm tra

```bash
npm run i18n:check                      # khoá/tham số giữa vi và en + chữ viết cứng trong src/
npm run i18n:check -- --files a.tsx     # chỉ quét chữ viết cứng trong các tệp này
npm run typecheck                       # sai khoá dịch = lỗi tsc
```

## Backend (backend/app/i18n)

- `app/i18n/locales/<locale>.json`: catalog phẳng theo nhóm, tham số kiểu `str.format` (`{count}`).
  Nhóm: `date.*` (thứ viết tắt), `price.*` (lý do gợi ý giá), `url.*` (lỗi URL watchlist),
  `holiday.*` (tên ngày lễ), `weather.*`, `csv.*` (tiêu đề cột, nhãn, tên tệp), `alert.*` (dòng
  cảnh báo), `email.*` (tiêu đề, khung, chân email). Khoá snake_case theo ý nghĩa.
- `t(locale, key, **params)`: thiếu khoá ở một ngôn ngữ → bản `vi` → chính khoá. Catalog nạp một
  lần mỗi tiến trình. **Số nhiều**: hai khoá `x.one` + `x.other` (tiếng Việt hai bản giống nhau),
  gọi `t(locale, "x", count=n)` tự chọn dạng.
- `normalize_locale(value)` → `"vi"|"en"` (mặc định `"vi"`); `parse_accept_language(header)`
  chọn ngôn ngữ hỗ trợ có q cao nhất.
- API: `LocaleDep` (`get_locale` trong `app/api/deps.py`, đọc `Accept-Language` qua `Request` nên
  OpenAPI không đổi). Hàm thuần trả mã + tham số, dịch ở biên API; schema giữ chuỗi.

| Chữ | Nơi sinh | Cách dịch |
|---|---|---|
| Lý do gợi ý giá | `market/price_suggest.py` (`Reason(key, params)`) | `reason_text(r, locale)` trong `routers/market.py` |
| Tên ngày lễ | `holidays/data.py` (mã → `holiday.<mã>`; `kind`, `group` ổn định) | `holidays_between(..., locale)`: overview, ngày, `/market/holidays`, pace. Giao diện dùng `HolidayOut.kind`/`group` (và `DayDetailOut.holiday_kind`), không dò theo tên |
| Lỗi URL watchlist | `UnsupportedUrl(key, **params)` ở `channels/registry.py`, `collector/*/urls.py` | `exc.message(locale)` trong `routers/watchlist.py`; `str(exc)` = bản `vi` (CLI, log) |
| Thời tiết | `routers/market.py` (`error`), `market/weather.py` (`lang` của OpenWeather) | `Accept-Language` |
| CSV | `export/csv_tables.py` | `overview_header/events_header/..._rows(..., locale)`, tên tệp `tong-quan`/`overview` |
| Email | `notify/alert_rules.py`, `render.py`, `fmt.py` | `tenants.insight_language` qua `TenantInfo.language` |
| Bản tin AI | `insight/*` | LLM viết theo `language` (user prompt ghi `en (English)`); ngày lễ trong input theo ngôn ngữ đó |

- Số/tiền/ngày trong email (`notify/fmt.py`, bảng `_STYLES` theo ngôn ngữ, mặc định `vi`): `vi`
  "1.250.000 ₫", "T7 03/10"; `en` "₫1,250,000", "Sat 03/10" (khớp `en-GB` của dashboard).
- **Ngôn ngữ báo cáo** (`tenants.insight_language`, Cài đặt › Lịch quét) quyết định bản tin AI,
  báo cáo tuần, email cảnh báo, email thử. API chỉ nhận mã trong `LOCALES` (sai → 422).
- Lỗi HTTP `detail` giữ tiếng Anh ổn định (frontend dịch qua `src/lib/errors.ts`), không đưa qua
  `t()`. Ngoại lệ duy nhất: lỗi URL watchlist (422) là câu hướng dẫn dạng URL của kênh, đã dịch.
- Không dịch: log, CLI, docstring/comment, mô tả OpenAPI, prompt hệ thống của LLM, dữ liệu thu từ
  kênh (tên gói/giá, `raw_text` tín hiệu cầu ghi lúc quét).
- `tests/unit/test_i18n.py`: các catalog cùng khoá và cùng tham số, `Accept-Language`, bản tiếng
  Anh của từng loại chữ.

## Thêm ngôn ngữ mới (ví dụ `ko`)

1. `dashboard/src/i18n/config.ts`: thêm `"ko"` vào `LOCALES`, `INTL_LOCALE`, `LOCALE_NAME`.
2. Chép `src/messages/en/` → `src/messages/ko/`, dịch từng tệp; thêm loader trong
   `src/messages/index.ts`.
3. Backend:
   - `app/i18n/__init__.py`: thêm `"ko"` vào `LOCALES`.
   - Chép `app/i18n/locales/en.json` → `ko.json` rồi dịch, kể cả `language.name` (tên ngôn ngữ
     ghi cho LLM ở user prompt) và `date.weekday.*`.
   - `app/notify/fmt.py`: thêm một dòng `_STYLES` (dấu nhóm hàng nghìn, mẫu tiền đồng) theo
     `INTL_LOCALE` của dashboard.
   - `market/weather.py` gửi mã ngôn ngữ thẳng cho OpenWeather; mã không được hỗ trợ thì
     OpenWeather trả tiếng Anh.
   - `insight_language` tự nhận mã mới (kiểm tra theo `LOCALES`). Thêm lựa chọn ở Cài đặt › Lịch
     quét của dashboard.
4. Chạy `npm run i18n:check`, `npm run typecheck`, `pytest tests/unit/test_i18n.py`.
